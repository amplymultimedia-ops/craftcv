Reverse-engineered behavior

Acceptance criteria

These criteria describe the current intended source behavior. Production verification is still required for account-only flows and the new auth deployment.

Public site and account access
  • AC-01: Landing navigation moves to the Features and Pricing sections; all primary calls to action route to sign-in.
  • AC-02: A visitor can submit an email from sign-in or registration and sees a confirmation naming the recipient when the request succeeds.
  • AC-03: A valid, unused magic link verifies the email, creates a new account when needed, stores a bearer token, and opens the dashboard.
  • AC-04: Missing, invalid, or expired verification tokens show an error and a route back to sign-in; links expire after 10 minutes.
  • AC-05: Dashboard, builder, billing, and settings redirect unauthenticated users to sign-in; sign-out clears the local token.
Dashboard and resume lifecycle
  • AC-06: Dashboard lists only the current user's resumes and cover letters, sorted by latest update.
  • AC-07: Creating a resume persists an empty Classic resume titled "Untitled Resume" and opens its builder.
  • AC-08: Duplicating creates a separate copy with the original content/template/tone and a "(Copy)" title; deleting removes the selected resume.
  • AC-09: Personal details, summary, experience, education, skills, and certifications update the preview and persist after the autosave delay.
  • AC-10: Rename commits on blur or Enter, reverts on Escape, and substitutes "Untitled Resume" for a blank title.
  • AC-11: Selecting any available template or tone updates the preview and persists the selection.
Job matching and generated content
  • AC-12: A user can submit pasted job text or a URL; successful parsing returns job details and keywords and stores the source ad.
  • AC-13: Tailored CV generation uses the baseline profile when present, otherwise the current resume, and saves the tailored result to the current resume.
  • AC-14: Cover-letter generation creates a saved letter associated with the current resume and displays a preview.
  • AC-15: Editing a letter supports rich text and debounced persistence; selected text can be rewritten with preset or custom instructions.
  • AC-16: Letter list cards support opening/editing and deletion; saving updates the existing user-owned letter.
Import and export
  • AC-17: Uploading a PDF, DOCX, or TXT file from the builder extracts profile data, persists a baseline profile, applies it to the current resume, and shows errors on failed parsing.
  • AC-18: Export opens the browser print dialog, and the user can choose whether to append the cover letter.
  • AC-19: Long resume content flows onto additional printed pages without being hidden by a fixed-height wrapper; an included cover letter begins after the resume.
Billing and account settings
  • AC-20: Selecting a billing plan records an active subscription and displays resulting status/date information without processing a payment.
  • AC-21: Cancel changes the subscription status; fetching status updates expired records. No app feature is gated by plan entitlement.
  • AC-22: Settings displays the authenticated account name/email and provides billing navigation and sign-out.
  • AC-23: Account deletion requires exact typed confirmation, deletes the current account and related product rows in a transaction, removes outstanding magic links, clears the local bearer token, and redirects to sign-in.
Service and failure behavior
  • AC-24: App API success responses are returned in the { data: ... } envelope; errors expose message/code fields. Better Auth endpoints are an exception.
  • AC-25: AI parsing/generation requires a functioning configured OpenAI or Ollama service; failures should not be interpreted as successful saved output.
  • AC-26: Production email delivery requires a valid Resend API key and authorized sender; the live API health/auth mismatch must be resolved before the Vercel frontend deployment is considered complete.

Known gaps

Deferred work and deployment blockers

These are the clearest differences between advertised behavior and the current implementation.

  • Auth deployment: Live login remains email/password; workspace source uses magic links.
  • Trial terms: Landing says 7 days; backend creates a 14-day trial. Payment is not connected.
  • Checkout: Pricing CTAs navigate to login and do not create a checkout session.
  • Entitlements: Subscription status does not restrict resume limits or paid functionality.
  • Backend deploy: Account deletion and magic-link changes are committed on branch release-candidate-local-ai; a Render Docker/Blueprint scaffold is included. Render lists the GitHub repository but its Blueprint flow reports a missing repository URL and 429, so no service was created.
  • Production API: The live auth session path returned HTTP 502 (DNS_HOSTNAME_NOT_FOUND); the currently referenced backend hostname also fails DNS resolution.
  • Public project configuration: The public craftcv Vercel project has no environment variables. Configure the correct backend URL there only after a healthy backend host is available.
  • Auth cutover: The live site still shows password login; backend and public CraftCV frontend must be released together and tested with a real email link. The protected webapp project remains on its previous production deployment.
  • Payment work deferred: Real checkout, payment-provider integration, subscription entitlements, trial/pricing copy alignment, and renewal/cancellation payment handling remain intentionally untouched until a payment account is configured.
  • PDF verification: Print CSS now permits page flow, but a long-resume PDF and cover-letter page-break check still requires a live authenticated session.
  • Legal review: Privacy and Terms routes are implemented with behavior-grounded copy; an owner/legal review is still advisable before treating them as final legal advice.
  • AI service dependency: Job parsing, tailoring, letter writing, rewrite, and document parsing need a configured and reachable model provider.
Audit basis: workspace frontend/backend source plus public Vercel landing, pricing, login, auth API health, and deployment dashboards observed on 2026-10-14. Local checks pass for the changed code, but no live account was used. Public production deployment is blocked pending a healthy backend host; payment tasks are intentionally deferred.
